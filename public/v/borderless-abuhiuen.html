The main finding: two Google Ads conversions before the form

  1. Opening /demo sends a Google Ads conversion (event page_view, conversion label 0iTHCK7X0coZEL7Yyo4q). It comes from a page-view rule set in your Google Ads tag for www.getborderless.co.uk/demo.
  2. Clicking a link to /demo sends a second one (label 9ESjCOrlxvAcEL7Yyo4q). The rule counts any click on something whose link contains /demo, so in my test it also fired when I clicked Accept on your cookie banner on /demo.

Your container also has separate conversions for the real form submit (label I67YCMqhwPAcEL7Yyo4q) and a RevenueHero booking (label tKbOCOuyu_AcEL7Yyo4q). So up to four conversions are set up along one path to a demo. I saw the first two fire. I didn’t test the other two.

What it means for your ad spend: if either of the first two is set to Primary, Google Ads is bidding towards people who open /demo, not people who ask for a demo, and the cost per demo it reports will look lower than it really is.

I ran this in a fresh browser where no cookie choice had been made. The Google Ads, Meta and LinkedIn tags still fired before I clicked anything on your cookie banner.

Why en=form_start on Accept: your cookie banner keeps its settings in a hidden form on /demo (id=cookie-preferences). Clicking Accept ticks its three checkboxes, and Google’s tags count that as someone starting a form. The same click sent GA4 a form_start for form_id=cookie-preferences. Your demo form wasn’t touched.

What I can’t see from outside

Which of these conversions are primary (used for bidding) and which are secondary (reporting only). That’s the one thing that decides whether this matters, and it’s a 5-minute check.

Your 5-minute self-check in Google Ads

  1. In Google Ads, go to Goals, then Conversions, then Summary.
  2. Look for conversion actions that count a page view of /demo, or a click to /demo. In the details of each one, the tag label will match one of these: 0iTHCK7X0coZEL7Yyo4q (demo page view) or 9ESjCOrlxvAcEL7Yyo4q (click to /demo).
  3. Check the column that says whether each action is Primary or Secondary.
  4. If either of them is Primary, your campaigns are bidding for page views and clicks as well as real demo requests.
  5. Set the date range to the last 30 days and add the All conv. column. Compare the conversions on the demo page-view action (0iTHCK7X0coZEL7Yyo4q) with the form-submit action (I67YCMqhwPAcEL7Yyo4q). The page-view action counts every visit to /demo and the form submit counts real requests, so if the page view is Primary, the ratio between the two shows roughly how far your demo count is inflated.
  6. While you’re there, check that the form submit (I67YCMqhwPAcEL7Yyo4q) and the RevenueHero booking (tKbOCOuyu_AcEL7Yyo4q) are the ones you actually want to bid towards.

For your developer: the fix

  1. In Google Ads, set the demo page view (0iTHCK7X0coZEL7Yyo4q) and click to /demo (9ESjCOrlxvAcEL7Yyo4q) actions to Secondary, or remove them. Keep the form submit and the booking as Primary.
  2. In GTM-WN5PP9J7, pause the Google Ads conversion tag with label 9ESjCOrlxvAcEL7Yyo4q. Its trigger is any click whose link contains /demo.
  3. Add the listener below as a Custom HTML tag on /demo, create the two Custom Event triggers, and use them as the only triggers on the form-submit (I67YCMqhwPAcEL7Yyo4q) and booking (tKbOCOuyu_AcEL7Yyo4q) tags. It counts one submit per page, even though the form is embedded twice on /demo, and it sends no form answers to the dataLayer.
  4. Test it in 2 minutes: open GTM Preview on /demo and click Accept. The tag with label 9ESjCOrlxvAcEL7Yyo4q should not appear under Tags Fired. Then submit one test request: demo_form_submitted should appear once, with the form-submit tag under Tags Fired. Delete the test contact in HubSpot afterwards.
GTM: Custom HTML, named "CL - demo form listener", trigger: Page View where Page Path contains /demo
<script>
/* One Google Ads conversion per real demo request.
   HubSpot legacy forms:  https://developers.hubspot.com/docs/cms/start-building/features/forms/legacy-forms
   HubSpot new editor:    https://developers.hubspot.com/docs/api-reference/latest/marketing/forms/global-form-events
   RevenueHero events:    https://help.revenuehero.io/integrations/javascript-events */
(function () {
  var FORM_ID = "54ee3573-251e-44c8-adbc-c03c48bc5566"; // if the form is rebuilt in HubSpot's new editor, check this ID still matches
  var sent = {};
  function push(name) {
    if (sent[name]) return; // one per page load, whichever embed or event reports it
    sent[name] = true;
    window.dataLayer = window.dataLayer || [];
    window.dataLayer.push({ event: name, form_id: FORM_ID });
  }
  // HubSpot forms from the updated editor
  window.addEventListener("hs-form-event:on-submission:success", function (e) {
    if (e.detail && e.detail.formId === FORM_ID) push("demo_form_submitted");
  });
  // HubSpot legacy forms, and RevenueHero bookings
  window.addEventListener("message", function (e) {
    var d = e.data;
    if (typeof d === "string") { try { d = JSON.parse(d); } catch (err) { return; } }
    if (!d || typeof d !== "object") return;
    if (d.type === "hsFormCallback" && d.eventName === "onFormSubmitted" &&
        (d.id === FORM_ID || (d.data && d.data.formGuid === FORM_ID))) push("demo_form_submitted");
    // RevenueHero's booking popup is served from popup.schedulehero.io, so keep schedulehero.io; revenuehero.io is allowed too.
    if (d.type === "MEETING_BOOKED" &&
        /^https:\/\/([a-z0-9-]+\.)?(schedulehero|revenuehero)\.io$/.test(e.origin)) push("demo_meeting_booked");
  });
})();
</script>
  • Custom Event "demo_form_submitted" → use as the only trigger on the form-submit conversion tag
  • Custom Event "demo_meeting_booked" → use as the only trigger on the booking conversion tag

Your demo form uses HubSpot’s legacy embed (embed/v2.js with hbspt.forms.create), and the listener handles both that and forms built in HubSpot’s updated forms editor, so it still works if the form is moved over.

Secondary findings

  1. Clicks to pricing and case studies count as conversions. A click on a link to getborderless.co.uk/pricing or /case-study sends a Google Ads conversion (label w-7yCJq2xPAcEL7Yyo4q). Phone-number clicks (tel: links) send another (label sxhDCO29lfEcEL7Yyo4q). I read this from your container; I didn’t click them.
  2. The ad click doesn’t travel with the demo request. The demo form has no hidden field for gclid or UTMs, and the “Book a demo” buttons on your homepage go to /demo with only a page label added (demo_source_page), so someone who lands on the homepage from an ad submits the form without them. Google Ads’ own tags still credit the ad through its first-party cookie, but anything built on the HubSpot record, such as offline conversion imports, won’t have it.
